Learn the algorithms

Two ways to explore the same graph

BFS

Breadth-First Search

Explores the graph level by level: the start node, then all of its neighbours, then all of their neighbours. It uses a queue (FIFO), so nodes discovered first are processed first.

Pseudocode

BFS(G, s):
  create empty queue Q and visited set
  mark s visited;  enqueue(Q, s)
  while Q is not empty:
      u ← dequeue(Q)            // front
      visit(u)
      for each neighbour v of u in G[u]:
          if v not in visited:
              mark v visited    // mark on enqueue
              enqueue(Q, v)     // back

When is BFS useful?

  • Shortest path in an unweighted graph (fewest edges)
  • Level-order processing, "degrees of separation"
  • Finding every node within k hops

Time O(V + E)Aux. space O(V)

DFS

Depth-First Search

Follows one path as deep as possible, then backtracks to the most recent node that still has unexplored neighbours. It uses a stack (LIFO) (or recursion, which is the call stack).

Pseudocode

DFS(G, s):
  create empty stack S and visited set
  visit(s); mark s visited;  push(S, s)
  while S is not empty:
      u ← top(S)
      if u has an unexplored neighbour v:
          if v not in visited:
              visit(v); mark v visited
              push(S, v)        // go deeper
      else:
          pop(S)                // backtrack

When is DFS useful?

  • Cycle detection and topological sorting
  • Maze solving and other backtracking problems
  • Finding connected / strongly connected components

Time O(V + E)Aux. space O(V)

Compare them

How are cycles handled?

A cycle (A → B → C → A) would make a naive traversal run forever. Both algorithms keep a visited set. Before using a neighbour they ask "have I seen this node?". If yes, the edge is skipped, so every node is processed exactly once and the algorithm always stops. The playback panel shows these as "skip" steps.

Why O(V + E) with an adjacency list?

Every vertex is enqueued/pushed and removed once (V work). While processing a vertex we scan only its own neighbour list. All lists together hold E entries for a directed graph (2E for undirected), so edges cost O(E) in total. An adjacency matrix would need to scan a whole row of V cells for every vertex, giving O(V²).

Why O(V) extra memory?

The visited set remembers up to V nodes. The queue (BFS) or stack (DFS) can also hold up to V nodes at once in the worst case, for example a star graph for the BFS queue, or a long path for the DFS stack. The adjacency list itself is the input, so it is not counted as auxiliary space.

Same bound, different shape

BFS's memory peaks with the widest level of the graph, DFS's with the deepest path. Both are O(V) in the worst case, but on a wide, shallow graph DFS uses far less memory, and on a long path BFS does.

About this project

DAA concepts demonstrated

Graph representation

Adjacency list stored in Python, built in O(V + E). Neighbours are ordered deterministically.

Abstract data types

A queue (collections.deque) powers BFS; a stack (a Python list) powers DFS.

Correctness

Each node is visited exactly once thanks to the visited set. Cycles and disconnected graphs terminate safely.

Asymptotic analysis

Time O(V + E), auxiliary space O(V), with the reasons shown on this page and in the README.

Client-server design

The browser sends the graph as JSON to a Flask REST API. The backend is the single source of truth. The browser only replays the steps it returns.

Testing

Automated pytest suites check traversal orders, FIFO/LIFO behaviour, cycles, disconnected graphs and API errors.
